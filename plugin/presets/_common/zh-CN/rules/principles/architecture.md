# 架构通用原则

> 跨技术栈的架构工程原则。各技术栈的具体实现见对应 preset 的 rules/architecture.md。

---

## 依赖方向

- 依赖方向只能向下（单向依赖）
- 禁止循环依赖
- 高层模块不应依赖低层模块的实现细节

---

## 模块隔离

- 模块间通过明确接口通信
- 隐藏内部实现细节，只导出公开 API
- 一个模块的修改不应导致其他模块的连锁变更

---

## 显式导出

- 使用 index 文件或导出声明控制公共 API
- 内部实现不应被外部直接访问
- 禁止通配符导出（`export *` / `import *`）

---

## 接口抽象

- 依赖抽象（接口/协议）而非具体实现
- 核心业务逻辑不应直接依赖具体框架或第三方库
- 外部依赖通过适配器隔离

---

## 关注点分离

- 每个模块/组件只负责单一职责
- 业务逻辑与技术基础设施分离
- 配置与代码分离
