# BR-002：预设模板库

> **归属**：OBJ-1（提升用户采用率）
> **优先级**：P0（核心产品能力）
> **就绪度**：85%

## 用户故事

**主故事**：作为个人 Claude Code 开发者，我希望根据项目技术栈快速获取预设模板，以便跳过从零搭建 .claude/ 目录的过程，立即获得高质量的上下文配置。

**次要故事**：作为团队 Leader，我希望团队成员使用统一的预设模板，以便保证 Claude 代码生成质量的一致性。

## 验收标准

- [ ] 每个预设包含 `preset.yaml` 配置文件
- [ ] 每个预设包含 `zh-CN/` 和 `en/` 双语版本
- [ ] 每个预设通过 `scripts/validate-presets.sh` 验证
- [ ] 模板占位符符合 `docs/template-variables.md` 规范
- [ ] 每个预设包含 `CLAUDE.md` 入口文件
- [ ] 每个预设包含 `rules/` 目录
- [ ] `rules/` 必选/可选规则由 `context-schema.yaml` 定义并校验
- [ ] 以上标准对现有 4 个预设（generic, python-fastapi, react-typescript, aws-cdk）均已满足

## 业务规则

1. **新增预设决策标准**：需有明确的社区需求（Issue/讨论）+ 技术栈持续活跃度，由维护者综合判断
2. **版本管理**：各预设独立版本号，按自身变更独立升版（记录在 `manifest.json` 中）
3. **复用机制**：`_common/` 为可选复用基座，各预设可引用其内容但不强制

## 非功能需求

### 可扩展性

- 提供标准化脚手架工具/命令，用于生成新预设的目录骨架
- 配套创建流程文档（`docs/customization-guide.md`）
- 有经验的贡献者创建一个新预设（从骨架到通过验证）≤ 4 小时

### 质量检查

在 `scripts/validate-presets.sh` 基础上，需覆盖以下检查维度：

1. **文档可读性**：无断链、无空 section、格式一致
2. **规则覆盖度**：`context-schema.yaml` 定义的必选规则必须存在
3. **双语一致性**：`zh-CN/` 和 `en/` 文件结构和 section 一一对应
4. **占位符完整性**：所有模板变量有默认值或说明
