# 通用信息架构原则

> **职责**：Claude Code 项目信息组织的 11 项通用原则。可跨项目复用。
>
> **定位**：通用理论层。各项目可基于这些原则制定自己的具体设计原则。
>
> **按需加载**：审视信息架构、创建新模板、审计文档结构时参考。

## 11 原则

| # | 原则 | 核心要求 | 应用指南 |
|---|------|---------|---------|
| IA-1 | 单向依赖 | 信息从抽象流向具体，不可反向 | 设计分层架构时，确保上层文件不依赖下层实现 |
| IA-2 | 抽象分层 | 不同抽象层级放在不同文件 | 通用原则与具体实现分文件定义，按层级组织目录 |
| IA-3 | 稳定-易变分离 | 高扇入文件隔离易变内容以保持稳定 | 将频繁变更的路径、版本号等提取到独立文件，高引用文件仅保留稳定内容 |
| IA-4 | 信息分类 | 不同信息类型不混放 | 规则、参考文档、项目文档等按类型分目录存放 |
| IA-5 | 按需加载 | 只加载当前上下文所需的最小信息集 | 将详细内容放在独立文件中，入口文件仅提供索引和链接 |
| IA-6 | 单一权威 | 每条信息有且仅有一个权威定义点 | 定义概念时选定唯一文件，其他文件通过链接引用，不复制内容 |
| IA-7 | 确定性分级 | 约束的执行保障级别匹配其关键程度 | 为约束标注级别（如铁律/必须/推荐），关键约束配备自动化检测 |
| IA-8 | 可发现性优先 | 入口信息为发现而设计，不为完整而设计 | 在文件开头放置速查卡片和索引表，帮助快速定位所需信息 |
| IA-9 | 认知清晰 | 面向 LLM 的指令精确无歧义，阻止合理化绕过 | 使用表格、矩阵等结构化格式表达复杂关系，避免模糊的散文描述 |
| IA-10 | 契约隔离 | 数据格式由独立契约层约束 | 模板变量、API 格式等定义在独立的规范文件中，与使用方解耦 |
| IA-11 | 单一职责 | 每个文件只有一个核心职责 | 在文件头部声明职责，内容超出职责范围时拆分为独立文件 |

## 约束分级标记

| 标记 | 含义 | 执行保障 |
|------|------|---------|
| `iron rule` | 铁律，不可违反 | 应有 Hook 或自动化测试 |
| `required` | 必须遵循 | 代码审查检查 |
| `recommended` | 推荐实践 | 最佳实践指引 |
