# Agent Harness 架构铁律

> 五层架构（L1 Contract → L2 Knowledge → L3 Skill → L4 Agent → L5 Entry）| 单一写入者 | 方法论归 Skill | 按需加载（≤150 行）

> 在此工作空间内开发任何 Plugin 组件时，本文件中的铁律自动生效。
> **P0**（必须）违反 → Agent 系统状态损坏，产出不可靠。

## IA 11 原则速查

| 原则（主标） | 索引 | 一句话规则 |
|------------|------|----------|
| **单向依赖** | IA-1 | 上层引用下层，下层禁止引用上层 |
| **抽象分层** | IA-2 | 概念层（原理）与操作层（步骤）放不同文件 |
| **稳定-易变分离** | IA-3 | 知识不嵌入 Skill 正文，通过路径引用 |
| **信息分类** | IA-4 | 步骤归 Skill、约束归 Hook、概念归 Knowledge、路由归 Command |
| **按需加载** | IA-5 | 知识文件 ≤150 行，索引先行，用时再加载 |
| **单一权威** | IA-6 | 角色定义只在 roles.md；状态只由 update-context.py 写入 |
| **确定性分级** | IA-7 | 铁律→Hook+HARD RULES；强约束→ANTI-RATIONALIZATION；推荐→文本 |
| **可发现性优先** | IA-8 | description 含触发短语，且**禁止摘要工作流**；知识目录 3+ 文件时有 _index.yml |
| **认知清晰** | IA-9 | 铁律用英文祈使句，禁止"如果...则..."条件结构 |
| **契约隔离** | IA-10 | 产出格式/角色权限/状态模型统一在 contracts/ 中定义 |
| **单一职责** | IA-11 | 一个 Skill 一个阶段；一个 Command 只做路由 |

## 层间依赖铁律（P0）

- L1/L2 文件禁止引用 L3-L5 任何文件
- L3 Skill 禁止引用 L4 编排器或 L5 入口层文件
- L4 编排器禁止引用 L5 入口层文件
- L3 Skill 必须通过路径引用 L1/L2，禁止内嵌知识内容

**违反检测与修复**：

| 检测模式 | 违反 | 修复动作 |
|---------|------|---------|
| L1/L2 文件出现 `skills/`、`agents/`、`commands/` 路径 | IA-1 | 删除路径引用 |
| L3 文件出现 `agents/` 路径 | IA-1 | 删除引用；Skill 通过读取产出文件与上游交互 |

## 约束执行分级

| 级别 | 关键程度 | 执行机制 |
|------|---------|---------|
| 铁律 | 最高 | Hook 校验 + HARD RULES（英文双重保障） |
| 强约束 | 中 | ANTI-RATIONALIZATION（英文封堵逃避） |
| 推荐 | 低 | 方法论工作流中的中文文本声明 |

判断标准：违反后系统状态被破坏 → 铁律；产出质量下降 → 强约束；偏离最佳实践 → 推荐。

## 附录：术语定义

| 术语 | 定义 | 判别标准 |
|------|------|---------|
| 方法论阶段 | 有明确输入/输出、可独立产出一个产物的步骤集。一个 Skill = 一个阶段 | 产出是否完成（非读写文件等原子操作） |
| 触发短语 | frontmatter `description` 中提示 Agent 何时激活该组件的关键短语 | 有效：`Use when...` / `当用户想要...`；无效：`This skill handles...`（功能描述非触发） |
| 方法论逻辑 | "如何完成某个方法论阶段"的步骤序列。区别于路由（归 Command）、结构校验（归 Hook） | 在 Skill 中删除后该阶段无法完成 → 是方法论逻辑 |
| 知识内容 | 可脱离具体步骤独立理解的原理、模式、案例描述 | 能独立成文、脱离本 Skill 也能被其他 Skill 引用 |
